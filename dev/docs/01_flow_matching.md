# 01 Flow Matching を最小の式で

## やりたいこと

ノイズ `eps` からデータ `x1` へ向かう「流れ」を学びます。
学ぶのは速度場 `v(x, t)` 一つだけです。

## 学習

1. データ `x1` を 1 件取る
2. 同じ形のノイズ `eps ~ N(0, I)` を引く
3. 時刻 `t ~ Uniform(0, 1)` を引く
4. 直線で混ぜる: `x_t = (1 - t) * eps + t * x1`
5. 正解の速度は `x1 - eps`（直線なので `t` に依存しません）
6. モデルの出力との MSE を下げる

実装は `src/learn_dit/flow/flow_matching.py` の 60 行ほどです。

```python
eps, t = sample_noise_and_time(x1)
x_t = interpolate(x1, eps, t)          # (1-t)*eps + t*x1
v_target = target_velocity(x1, eps)    # x1 - eps
loss = masked_mse(model(x_t, t, **cond), v_target, mask)
```

ここで押さえる点は 3 つです。

- `t=0` で `x_t` はノイズそのもの、`t=1` でデータそのものになります（`tests/test_flow_matching.py` で確認）
- 速度はノイズからデータへ向く向きです。符号を逆にすると生成が発散します
- `t` はサンプルごとに違う値です。バッチ内で全時刻をまとめて学んでいます

## 生成

`t=0` のノイズから出発し、Euler 法で `t=1` まで進めます。

```
x <- x + (1 / steps) * v(x, t)
```

速度が本当に一定なら 1 ステップでも正確に着きます（テストで検証しています）。
実際の学習済みモデルでは `v` が場所によって変わるので、ステップ数を増やすほど誤差が減ります。
`sample` は 4 / 8 / 16 / 32 ステップを同じ初期ノイズで並べて保存するので、
「どこから形が崩れるか」を目で比べられます。

## 損失マスク

PushT ではエピソード終端で未来ステップが足りません。
足りない部分は最後の値で埋め、`mask=0` にして損失から除外します。
埋めた値を学習してしまうと「終端で止まる」挙動を覚えてしまいます。

## よくある勘違い

- **ノイズ予測ではない**: DDPM のようにノイズを当てるのではなく、速度を当てます
- **`t` はステップ数ではない**: `t` は 0〜1 の連続値で、Euler のステップ数とは独立です
- **スケジューラは無い**: 直線補間なので `beta` の設計が要りません。ここが実装の軽さにつながります
