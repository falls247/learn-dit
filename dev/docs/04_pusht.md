# 04 PushT — 観測条件付き動作生成

画像生成と同じ枠組みで、今度は**動作**を生成します。
変わるのは「何を生成するか」と「何で条件付けるか」だけです。

## タスク

`lerobot/pusht` の 206 エピソードを使います。seed 42 で **185 / 21** に分割します。
取得リビジョンは `data/pusht/meta.json` に記録します。

| | 内容 |
| --- | --- |
| 観測 | 直近 2 時点の 96×96 画像 + 2 次元の自機位置 |
| 生成対象 | 未来 16 ステップの 2 次元目標位置 |
| 実行 | 先頭 8 ステップだけ実行して再観測（receding horizon） |

16 ステップ生成して 8 ステップしか使わないのは、先の予測ほど当たらないためです。
半分捨てる代わりに、観測を早めに取り直します。

## 前処理で決めた約束

- **時刻対応**: フレームと位置・動作を `(episode_index, frame_index)` で突き合わせ、連番でなければ失敗させる
- **正規化**: 位置と動作を `[-1,1]` に min-max 変換。統計は**学習エピソードだけ**から作る（検証データの情報を混ぜない）
- **エピソード境界**: 系列はまたがない
- **履歴不足**: エピソード先頭では先頭観測を複製する
- **未来不足**: 終端では最後の値で埋め、`mask=0` で損失から除外する

学習中に毎回 mp4 をデコードしないよう、`prepare` でエピソード単位の npz に落とします。

## 評価

```bash
uv run learn-dit evaluate --task pusht --checkpoint outputs/pusht/<run>/checkpoints/best.pt
```

`gym-pusht` 上で「16 ステップ生成 → 8 ステップ実行 → 再観測」を繰り返します。
**同じ 20 個の初期化 seed** で未学習モデルと学習後モデルを回し、次を JSON に残します。

- 成功率
- 最大到達報酬（成功しなくても、どこまで近づいたかが分かる）
- 1 回の生成にかかった平均推論時間

先頭 2 本は MP4 も保存します。動画を見ると、失敗の質（届かない / 通り過ぎる / 震える）が分かります。

## 成績が低いとき

低い数値もそのまま記録してください。30 分の学習で成功率が出ることは保証していません。
確認する順序は次が有効です。

1. 損失曲線が下がっているか
2. `sample` の軌跡がデータセットの軌跡と同じ向き・尺度か（正規化の往復ミスは軌跡の潰れとして出ます）
3. 未学習モデルの最大到達報酬と比べて改善しているか
