# ADR: PushT の前処理を npz 中間形式に落とす

- 日付: 2026-09-12
- 状態: 採用

## 背景

`lerobot/pusht` は動画（mp4）と表形式データで構成されます。
学習時に毎ステップ動画をデコードすると、GPU より先にデータ供給が律速になり、
1,800 秒という時間上限の中で学習ステップ数が稼げません。

## 決定

`prepare` でエピソード単位の `.npz`（uint8 画像・位置・動作・frame_index）に変換し、
学習はこの中間形式だけを読む。取得リビジョンとエピソード長は `meta.json` に記録する。

## 理由

- 96×96 の uint8 なら 1 エピソード分がメモリに載る大きさで、デコードを 1 回に減らせます。
- 時刻対応（`frame_index` が連番か）を前処理時に一度だけ検証でき、
  学習ループから整合性チェックを外せます。
- リビジョンを記録するので、データ側が更新されても実験の再現条件が残ります。

## 結果

- 良い点: 学習が I/O ではなく計算律速になる。データ整合性の検証点が 1 箇所に集まる。
- 悪い点: ディスクを追加で消費する。`prepare` の実行が必須の手順として増える。
- 依存: `lerobot` のバージョン差は `prepare` に閉じ込め、import 経路とキー名の
  候補を順に試す形にした（`dev/docs/05_verification.md` に要調整点を記録）。
